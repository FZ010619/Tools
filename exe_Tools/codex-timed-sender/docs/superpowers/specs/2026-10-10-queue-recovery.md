# Codex 队列恢复投递规格

## 目标

把单条定时投递升级为本地持久化消息队列：用户可预先编辑多条消息，填写 Codex 的额度恢复时间后，程序在该时间自动按顺序投递。

## 约束

- 仅支持 Windows、本地 Tkinter 和 Python 标准库；不增加运行时依赖。
- 不读取账号、Cookie、凭据或 Codex 界面来判断额度。恢复时间由用户从“设置 → Usage”手动填写。
- 队列保存在 `%LOCALAPPDATA%\\CodexTimedSender\\queue.json`；测试可传入临时路径。
- 本地文件仍以路径文本发送；图片仍通过剪贴板作为附件粘贴。
- 目标窗口句柄不持久化；程序重新打开后必须重新绑定一次目标窗口。

## 队列行为

- 每项保存唯一标识、文本、文件路径、可选图片、Enter/Ctrl+Enter、创建时间及状态。
- 状态为“待发送 / 已发送 / 发送失败”。新建、编辑、删除与上移/下移均立即持久化。
- 队列有全局恢复时间、投递间隔（默认 15 秒）与暂停开关；这些设置也持久化。
- 到恢复时间且未暂停、已绑定有效目标窗口时，投递最早的待发送项；成功后标记已发送，等待间隔，再处理下一项。
- 发送失败时，该项保留为“发送失败”，自动暂停，用户可在修正窗口或内容后点击继续。
- 可选“首条需确认”：到恢复时间先发送一条；在用户点击继续前不发送后续项。默认关闭，以满足自动连续投递。
- 已发送项目保留在列表中供查看；用户可删除。

## 界面

- 保持现有绑定窗口、文本、文件、图片与发送键编辑区域。
- 增加“加入队列 / 更新选中项 / 新建草稿”、队列列表、删除/上移/下移按钮。
- 增加额度恢复时间、间隔、首条确认、启动/暂停队列和继续队列按钮，以及清晰的运行状态文本。
- 只在用户点击“启动队列”后按恢复时间投递；关闭应用不驻留后台。

## 不在本次范围

- 自动查询 Codex 账号额度、网页抓取、读取登录信息。
- 多项目/任务目标模板、云同步、系统开机启动、通知服务。
